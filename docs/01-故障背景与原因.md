# 01 故障背景与原因

本案例针对 Windows 10 Enterprise LTSC 2021，21H2，19044.1620，x64。原版 Computer Use 能枚举窗口、读取可访问性文字，但在普通资源管理器窗口请求截图时失败。对应软件版本和文件哈希见 [使用与回退](03-使用与回退.md)。

**已在指定版本、本机资源管理器场景验证原生截图恢复；其他版本和业务场景未据此获得验证。** 本页解释原始故障，具体处理方法见 [修复方案](02-修复方案.md)。

## 表现与系统能力

| 检查项 | 原版实测结果 |
| --- | --- |
| `sky.list_windows()` | 成功 |
| `include_text: true`，关闭截图 | 成功，文本树非空 |
| `include_screenshot: true` | `SetIsBorderRequired failed: 不支持此接口 (0x80004002)` |
| WGC 类型存在 / `IsSupported()` | True / True |
| `IsBorderRequired` 属性存在 | False |
| `IsCursorCaptureEnabled` 属性存在 | True |
| `UniversalApiContract` v12 | False |

文字读取使用 UI Automation，截图使用 WGC。文字成功并不代表图像捕获成功；备用桌面工具的成功也不能证明原生窗口接口已经恢复。

## 阻断点一：缺少可选的边框接口

原生后端尝试调用 `GraphicsCaptureSession.IsBorderRequired` 关闭捕获边框，而本机没有这个属性。Microsoft 将其引入版本标为 **10.0.20348.0 / UniversalApiContract v12**，与本机的能力探测结果吻合。[Microsoft API 说明](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.capture.graphicscapturesession.isborderrequired)

基础 WGC 已存在，缺失的是后来新增的边框控制接口。因此，应在接口不可用时保持系统默认边框，继续捕获。安装 Windows SDK、Python 包或常见运行库，并不能让旧系统自动获得该操作系统接口。

仅保留默认边框还不足以修复本案例：这样处理后，错误会继续推进为 `FrameArrived timed out`。

## 阻断点二：帧回调内等待图像转换超时

独立 WGC 对照确认，系统能够产生有效捕获帧。问题出现在 `FrameArrived` 回调内部同步等待 `SoftwareBitmap.CreateCopyFromSurfaceAsync` 的转换结果：

| 对照方式 | 本机结果 |
| --- | --- |
| 只获取 WGC 帧 | 成功，尺寸有效 |
| 在帧回调内等待异步表面转换 | 已收到帧，但转换等待超时 |
| 将同一转换放到独立 MTA 线程 | 成功 |
| 在回调内同步读取 D3D11 纹理并生成位图 | 成功 |

因此，`FrameArrived timed out` 在本案例中不能直接解释成“系统没有产生画面”。`CreateFreeThreaded` 的帧事件运行于内部工作线程；回调中的阻塞等待需要单独处理。[Microsoft 文档](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.capture.direct3d11captureframepool.createfreethreaded)

OpenAI 仓库中也有用户报告类似的转换等待问题；它提供了排查方向，本案例结论仍以本机对照和最终官方接口验收为依据。[相关报告 #35446](https://github.com/openai/codex/issues/35446)

## 结论边界

- 本机缺少可选接口和转换等待超时分别得到验证；不能概括为“WGC 不可用”或“少装了某个组件”。
- 对照测试覆盖主屏、左侧竖屏、窗口和 WARP 软件设备，未将故障归因于某个虚拟显示驱动。
- Codex 捆绑 PowerShell 的 CET 启动错误是另一个问题。本项目采用系统 Windows PowerShell 5.1 执行诊断，相关说明见 [常见问题](03-使用与回退.md#常见问题)。
- 原生截图的恢复结论来自官方 `@oai/sky` 调用和图片目视检查，不由调用无异常、图像非纯色或备用工具成功单独推定。

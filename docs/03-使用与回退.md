## 检查环境和当前状态

在项目根目录打开 Windows PowerShell，设置以下路径。本例使用已验证的运行时目录，其他安装位置通过现有参数显式指定；脚本不自动发现其他运行时，也不支持未验证的原程序版本。

```powershell
$windowsPS = Join-Path $env:SystemRoot 'System32\WindowsPowerShell\v1.0\powershell.exe'
$nativeDir = Join-Path $env:LOCALAPPDATA 'OpenAI\Codex\runtimes\cua_node\df473e5367fa2b42\bin\node_modules\@oai\sky\bin\windows'
$buildDir = Join-Path (Get-Location).Path 'artifacts\build\wgc-readback-v2'
$backupDir = Join-Path (Get-Location).Path 'artifacts\backups\wgc-readback-validated-20260921'

& $windowsPS -NoProfile -ExecutionPolicy Bypass -File .\scripts\diagnose-windows.ps1
& $windowsPS -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-wgc-readback.ps1 -Mode Status -NativeDirectory $nativeDir -BackupDirectory $backupDir
```

诊断脚本只读取系统状态，并将结果写入 `artifacts/diagnostics/windows.json`，可用 `-OutputPath` 指定其他输出路径。与本案例相符的能力组合是 WGC 可用、`IsBorderRequired: false`。`Status` 不修改安装；已修复时应显示 `IsReadbackCompat: true`、`CompanionMatches: true`、`BackupExists: true`。

确认当前程序的哈希和签名：

```powershell
Get-FileHash -LiteralPath (Join-Path $nativeDir 'codex-computer-use.exe') -Algorithm SHA256
Get-AuthenticodeSignature -LiteralPath (Join-Path $nativeDir 'codex-computer-use.exe') | Select-Object Status
```

本案例已经安装并验收，无需再次执行 Apply。下面的构建和安装流程适用于尚未修改、且与上表匹配的原程序。

## 构建和安装

先准备上表中的 LLVM-MinGW，使 `clang++` 在 PATH 中可用。Python 的原生构建依赖独立列在 [requirements-native.txt](../requirements-native.txt)：

```powershell
python -m pip install -r requirements-native.txt
clang++ --version
python tools\build_wgc_compat.py --native-dir $nativeDir --output-dir $buildDir
```

构建只生成 `codex-computer-use.compat.exe`、兼容 DLL 和清单，不修改安装目录。输出目录必须不存在；生成后按上表核对哈希。原版哈希不匹配时，脚本会在构建前拒绝执行。

已安装修复后，如需复现构建，可使用完整原版备份，并指定一个尚不存在的输出目录：

```powershell
python tools\build_wgc_compat.py --original-exe (Join-Path $backupDir 'codex-computer-use.original.exe') --output-dir .\artifacts\build\wgc-readback-rebuild
```

安装使用准备好的构建目录和新的备份目录。备份目录已存在时脚本会拒绝覆盖；若另选目录，应记录它，并在以后 Status 和 Rollback 时使用同一路径。

```powershell
& $windowsPS -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-wgc-readback.ps1 -Mode Apply -NativeDirectory $nativeDir -BuildDirectory $buildDir -BackupDirectory $backupDir
```

脚本校验原版、系统能力及候选文件，完整备份后只停止匹配的原生辅助进程，等待其光标管理子进程退出，再替换文件。存在多个辅助会话或其他版本时会拒绝继续。安装成功只代表部署完成，仍需通过下面的官方接口验收。

## 官方接口验收

在 Computer Use 提供的 `node_repl` 会话中导入 `@oai/sky`，调用 `sky.list_windows()`，从真实返回列表选择唯一的资源管理器窗口。按应用授权流程取得允许后，用 `sky.get_window_state` 同时请求 `include_screenshot: true` 和 `include_text: true`。

验收需同时满足：

- 返回真实图片和非空文字；目视确认窗口内容、清晰度及是否缺失区域。
- 连续三次调用均能得到新的图文结果，而非只检查调用没有抛异常。
- 安装状态与本页的版本、文件哈希一致，原版备份仍完整。

本案例已验证资源管理器图文读取及完整回退后重装。微信小程序等业务页面、HDR、截图坐标点击、完整 Codex 更新或重启尚未验收。未经独立测试的系统、应用和版本不自动获得相同结论。

## 回退到原程序

使用安装时的同一 `$nativeDir` 和 `$backupDir`。若重新打开 PowerShell，先按前面的路径设置重新定义变量，再执行：

```powershell
& $windowsPS -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-wgc-readback.ps1 -Mode Rollback -NativeDirectory $nativeDir -BackupDirectory $backupDir
& $windowsPS -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-wgc-readback.ps1 -Mode Status -NativeDirectory $nativeDir -BackupDirectory $backupDir
```

回退应得到 `IsOriginal: true`、`IsReadbackCompat: false`、`Signature: Valid`。脚本核验备份清单与哈希，只删除本次匹配的兼容 DLL，拒绝覆盖其他原生版本。回退会恢复原版在本机上的截图兼容问题。

保留整个原版备份目录，不能只保留清单。当前案例的有效备份和构建产物分别位于 `artifacts/backups/wgc-readback-validated-20260921/`、`artifacts/build/wgc-readback-v2/`，均不上传 GitHub。

## 备用桌面截图

备用工具不要求 LLVM-MinGW 或 pefile，依赖见 [requirements.txt](../requirements.txt)：

```powershell
python -m pip install -r requirements.txt
python tools\capture_screen.py --list-monitors
python tools\capture_screen.py --full
python tools\capture_screen.py --monitor 2
python tools\capture_screen.py --crop=0,0,1000,700 --crop-space screen
```

显示器编号以本次枚举为准，`--monitor 2` 只是示例。默认将 PNG 和同名 JSON 存入 `artifacts/screenshots/`；可通过 `--output artifacts\screenshots\example.png` 指定新路径，已有文件不会被覆盖。

裁剪矩形为左、上、右、下，单位是物理像素，右、下边界不包含在结果内。`image` 以整张虚拟桌面图左上角为原点，是默认坐标系；`screen` 使用 Windows 坐标，允许负值。工具按 `image = screen - virtual_origin` 转换，不要求读者具有与本案例相同的显示器布局。

窗口遮挡、最小化和受保护内容可能影响结果。备用工具不返回官方 `screenshotId`，其图像坐标不能直接当作官方窗口点击坐标；截图结果本身也不证明原生接口已经修复。

## 常见问题

| 现象或疑问 | 说明与处理 |
| --- | --- |
| `node_repl` 是什么，CC Switch 是否导致故障 | 它提供加载 `@oai/sky` 的 JavaScript 环境。本案例中配置的服务能够启动、执行 JavaScript 并枚举窗口，没有证据说明 CC Switch 导致截图故障；修复未修改 CC Switch 或 Codex 配置。 |
| 已启用 MCP，但任务工具列表没有 `node_repl` | 配置状态、服务能否运行、模型获得的工具列表是不同检查项。本案例未确认工具列表缺项的应用侧原因；原生验收通过标准 MCP 调用已配置的官方服务完成，不表示工具列表缺项也已修复。 |
| `Allow Codex to use explorer?` | 这是 Computer Use 自身的应用授权，应由用户按本次用途决定；兼容补丁不会自动批准应用访问。 |
| PowerShell 报 CET 错误 | 本机捆绑的 PowerShell 曾在启动时失败；上面的命令显式调用可工作的系统 Windows PowerShell 5.1。进程级 `-ExecutionPolicy Bypass` 不改变全局策略，也不是截图故障的修复。 |
| 原版、候选文件或 DLL 哈希不匹配 | 停止应用补丁，核对版本、源码和编译器；不修改脚本白名单来强行通过。 |
| 构建或备份目录已经存在 | 保留现有备份，改用新目录；回退始终使用该次安装实际生成的备份。 |
| 备用工具提示无法访问桌面或 `screen grab failed` | 检查是否为活动、解锁的桌面，以及当前会话和沙箱条件，不能直接归因于缺少边框接口。 |
| 布局变化、裁剪越界、纯色或输出已存在 | 重新枚举显示器并检查选区；为输出选择新路径。纯色检查不是内容正确性的证明。 |

当前 CLI 参数、默认安装位置和哈希保护保持不变。应用更新或安装路径变化后，先重新检查状态和版本；优先采用经过验收的厂商兼容更新。
